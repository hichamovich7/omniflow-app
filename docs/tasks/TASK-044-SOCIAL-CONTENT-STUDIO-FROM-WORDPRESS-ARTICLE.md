# TASK-044 — Social Content Studio from WordPress Article

Date: 2026-09-26

Status: PLANNED — documentation only. Nothing here is implemented, and this is not the active task. Every file, route, table and contract below is a proposal to confirm against the code at implementation time and the open decisions (section 7).

Related audit: `docs/tasks/AUDIT-WORDPRESS-PIPELINE-AND-MODELS-2026-09-26.md`.

## Goal

Add a clearly visible **Generate Social Content** button on the detail page of a WordPress article generated by OmniFlow (`/wordpress/[id]`). It turns that article into platform-adapted content for several networks. **Content only — never automatic publishing.**

Initial platforms to study: Pinterest, Facebook, Instagram (post), Instagram Reel, TikTok, Medium, and LinkedIn if the architecture allows it at no extra cost.

## Expected behavior

1. Available only from an existing, `completed` article owned by the caller.
2. Opens a generation interface (dialog or sub-page — decision D1).
3. One or more platforms can be selected.
4. Number of variants per platform can be chosen (bounded — decision D2).
5. The article's title, content, SEO keywords, meta description, featured + internal images and published URL (`wp_post_id` / site URL when known) are pulled automatically, server-side.
6. Format, tone and length are adapted per platform (table below).
7. Generation produces content only. No platform API call, no scheduling, no publish.
8. Results can be reviewed, edited, copied and exported.
9. Every generation is kept in history.
10. The original article (`wordpress_articles`, `wordpress_article_images`, storage files) is **never** modified.

### Per-platform output (v1)

| Platform | Fields |
| --- | --- |
| Pinterest | title (≤ 100), description (≤ 500), keywords, destination link = article URL, suggested board, image choice (existing article image or new image — D3/D4) |
| Facebook | post text, hook first line, link, hashtags (few), CTA |
| Instagram post | caption (≤ 2 200), first-line hook, hashtags (≤ 30), alt text, image choice, "link in bio" CTA |
| Instagram Reel / TikTok | hook (0-3 s), short script, suggested scenes/shots, on-screen text per scene, voice-over, caption, hashtags, CTA — **no video is generated** (no video pipeline exists) |
| Medium | title, subtitle, adapted article body (Markdown, canonical link to the original — D14), tags (≤ 5) |
| LinkedIn (optional) | post text (≤ 3 000), hook, CTA, hashtags (few) |

All text in the article's language (`wordpress_generations.language`), same four supported languages (en, de, es, fr).

## Proposed architecture (to confirm)

```text
/wordpress/[id]  → button "Generate Social Content" (only when article.status = completed)
→ Social Content Studio (platforms, variants, optional instructions)
→ POST /api/wordpress/[id]/social
    auth → rate limit / trial cap → Zod → ownership (wordpress_generations.user_id = auth.uid())
    → article completed? else 404/409 → [credits check — TASK-011]
    → INSERT social generation (processing)
    → per platform: generateText (role per D12) with a platform prompt, Zod-validated JSON
    → INSERT social contents → status completed / partial / failed
    → [register transaction + update balance — TASK-011]
→ review list (per platform, per variant): edit (PATCH), copy, export
→ GET /api/wordpress/[id]/social — history for that article
```

The article row is read with a `select` only; no route in this task writes to `wordpress_articles` / `wordpress_article_images` / `wordpress-images`.

## Open decisions (need founder approval)

| # | Decision | Options | Proposal |
| --- | --- | --- | --- |
| D1 | UI surface | Dialog on `/wordpress/[id]` vs dedicated sub-page `/wordpress/[id]/social` | Sub-page (history + editing need room) |
| D2 | Grouped vs separate generation; variants | One AI call per platform vs one call for all; 1 vs N variants | One call per platform (isolated failures, platform-specific budget); 1-3 variants, default 1 |
| D3 | Images | Reuse article images only vs generate extra social images | v1: reuse article images only, no image cost |
| D4 | Pinterest image from the article | Reuse featured image as-is vs generate a 2:3 Pin (AI Integrated) vs create real `pins` rows in a Pinterest generation | v1: text + reuse; a real Pin pipeline from an article is a follow-up task |
| D5 | Storage | New `social_generations` + `social_contents` tables vs JSON column on article | New tables; `social_contents.payload jsonb` per platform, validated by Zod |
| D6 | Credits | Free in v1 (rate limit + trial only) vs cost per platform/variant | Follow TASK-011 when shipped; until then rate limit + trial counter, as WordPress today |
| D7 | Edit before export | Allowed, and whether edits overwrite or version | Allowed; overwrite the social content row, keep `edited_at`; never the article |
| D8 | Export | Copy per field, TXT, CSV, JSON | Copy + JSON for all; Pinterest via existing CSV format; TXT per platform |
| D9 | Direct publishing later | Out of scope v1 | Out of scope; `publish_status` column not added until needed |
| D10 | Language | Article language only vs selectable target language | Article language only in v1 |
| D11 | Article URL | Require a published article vs allow a placeholder link | Allow generation; use the WordPress link when `wp_post_id` + site exist, else a visible `{{ARTICLE_URL}}` placeholder the user must fill before export |
| D12 | AI model per platform | FAST for all vs SMART for Medium | FAST for short formats; Medium on the article's text role. Model choice follows the audit's pending benchmark; no model change in this task |
| D13 | Limits & cost | Max platforms × variants per request, max article length sent | ≤ 7 platforms × ≤ 3 variants; article body truncated to a documented token budget |
| D14 | Medium duplicate content | Adapted rewrite with canonical link vs summary + link | Adapted version + canonical link note; never a verbatim copy |
| D15 | Permissions & RLS | Ownership via `wordpress_generations.user_id` chain vs denormalized `user_id` | Denormalized `user_id` on `social_generations` with `user_id = auth.uid()` RLS; contents inherit via FK |
| D16 | Original article preservation | — | Hard rule: read-only access to article tables, covered by tests |
| D17 | Reels/TikTok duration | 15 / 30 / 60 s | Selectable, default 30 s |

## Tests to plan

Unit / offline (`npx playwright test --project=renderer`, no network, no AI call — the text service is stubbed):

* Request schema: at least one platform, known platforms only, variants bounds, UUID article id.
* Per-platform output schemas: required fields, length limits (Pinterest 100/500, Instagram 2 200 / 30 hashtags, LinkedIn 3 000, Medium ≤ 5 tags), Reel/TikTok has hook, script, scenes, on-screen text, voice-over, caption, hashtags, CTA and **no** video field.
* Prompt builders: article language propagated; article title/keywords/URL present; placeholder used when no URL; with and without images (no image field when the article has none).
* Orchestration with a stubbed `generateText`: one platform failing does not drop the others (`partial`); invalid JSON is rejected, not repaired.
* Export: JSON round-trip, Pinterest CSV columns identical to `lib/csv/pinterest.ts`, TXT per platform.

API (route-level, mocked Supabase + AI):

* 401 without session; 404 unknown article; 403/404 article of another user; 409 article not `completed`.
* Rate limit / trial cap returns the standard error.
* Credits: insufficient balance → refused before any AI call (once TASK-011 exists); otherwise not charged.
* No write to `wordpress_articles` / `wordpress_article_images` / `wordpress-images` during generate, edit or delete (spy on the Supabase client).
* No outbound call to any platform or WordPress publish endpoint.
* History saved: generation + one content row per platform/variant.

Playwright E2E (`tests/playwright/wordpress-social-content.spec.ts`, AI route mocked):

* Button visible on a completed article, absent/disabled otherwise.
* Open studio → select Pinterest + Facebook → generate → both cards shown.
* Reel/TikTok script sections rendered; Medium article rendered.
* Edit a field → save → reload → edit persisted; original article unchanged on `/wordpress/[id]`.
* Copy and export actions; no "Publish" action exists.
* History lists the previous generation after reload.
* Article in German → UI shows German content (language badge) — mocked response, asserts the request carries `de`.
* Article without images → generation works, no image selector.

## Success criteria

* A completed article shows **Generate Social Content**; the user selects platforms and variants and gets reviewable, editable, copyable and exportable content per platform, in the article's language.
* Nothing is ever published; the original article and its images are byte-for-byte unchanged.
* History is persisted with RLS; another user cannot read or edit it.
* Credits / rate limits follow the approved decision D6.
* Tests above pass; TypeScript, ESLint and build pass.
* `docs/DATABASE.md`, `docs/API.md`, `docs/UI_UX.md`, `docs/TESTING.md`, `docs/DECISIONS.md`, `docs/CHANGELOG.md`, `docs/TASKS.md` and the in-app Guide (`lib/guide/content.ts`) are updated.
